# 社区平台查询指南

社区查询用于补充玩家实战经验，不是每个问题的必选步骤。统一使用 OpenCLI；执行前按 `SKILL.md` 检测依赖，缺失时先询问用户是否安装。

## 通用原则

1. 先用 OBC/BWiki 核对事实，再读取社区观点。
2. 按相关性、证据质量、适用版本、发布时间与互动数据综合筛选，不设固定点赞或播放门槛。
3. 新角色或新版本优先时效，成熟角色优先有机制解释、样本或计算依据的内容。
4. 不把单篇帖子写成“玩家共识”；至少两条独立内容一致时才能概括为“多条讨论倾向”。
5. 只读公开内容；不要发帖、评论、点赞或执行其他写操作。
6. 登录应在用户本机浏览器完成，不要求用户把 Cookie、令牌或账号凭据粘贴到对话中。

## 小红书

```bash
opencli xiaohongshu search "胡桃配装" -f json
opencli xiaohongshu note "NOTE_URL" -f json
```

`NOTE_URL` 必须取自搜索结果并保留完整查询参数，尤其是 `xsec_token`。不要使用裸 `note_id` 请求详情。

适合提取：充能手感、低成本平替、新手误区、深渊实战。引用时记录标题、完整 URL、发布时间和互动数据；互动数取不到就不编。

## 知乎

```bash
opencli zhihu search "那维莱特圣遗物" -f json
opencli zhihu question "QUESTION_URL_OR_ID" -f json
```

优先有机制分析、计算过程或明确配装前提的回答。旧回答只有在机制未变化且能核对时才使用，并标注原发布时间。

## B站

```bash
opencli bilibili search "芙宁娜配装攻略" --limit 5 -f json
opencli bilibili video "BV号" -f json
opencli bilibili subtitle "BV号" -f json
```

视频只作攻略参考。若实际使用了视频观点，应读取详情或字幕，而不是只根据标题概括；引用时记录标题、UP 主、完整 URL、发布时间与播放量。

## 查询策略

| 用户意图 | 建议社区集合 |
|----------|--------------|
| 稳定图鉴事实 | 不查询社区 |
| “大家怎么配” | 小红书 + 知乎，必要时补 B站 |
| 机制深度分析 | 知乎 + 有字幕/正文的 B站内容 |
| 深渊实战 | 小红书或 B站，必须核对期数/日期 |
| 视频推荐 | B站，先核对视频适用版本 |

互不依赖的查询可由 Agent 使用自身并行能力执行，不要在跨平台说明中假设特定 Shell 的后台任务语法。

## 失败处理

- 单个平台失败不影响其他来源。
- 所有社区平台失败时，仍可用 OBC/BWiki 回答事实和已核对的攻略内容。
- 清楚写明哪些社区来源未覆盖，不把缺少社区数据说成“社区一致”。
- OpenCLI 报未登录时，请用户在本机浏览器登录对应平台后重试；不要索取 Cookie 文本。

## 引用格式

```markdown
- [社区经验·小红书] <标题与 URL>（发布：YYYY-MM-DD；互动：...）
- [社区经验·知乎] <标题与 URL>（发布：YYYY-MM-DD；赞同：...）
- [社区经验·B站] <标题与 URL>（UP：...；发布：YYYY-MM-DD；播放：...）
```
